# Google setup

1. Create a Google Cloud project and enable Gmail API and Google Calendar API. Enable Routes API only if live ground-route estimates are needed. Public travel web search uses Brave Search and does not require a Google API.
2. Configure the OAuth consent screen for the intended account and test users.
3. Create a Web application OAuth client. Set its authorized redirect URI exactly to `GOOGLE_REDIRECT_URI`; the application's default callback is `http://localhost:3000/auth/google/callback` (`GET /auth/google/callback`).
4. Set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` together. Set `GOOGLE_ALLOWED_EMAIL` to the single account TripSync may connect; production OAuth requires it. Never commit credentials.
5. When PostgreSQL is enabled, generate `TOKEN_ENCRYPTION_KEY` as canonical base64 for 32 random bytes and protect it separately from the database. Run `npm run db:migrate` before starting.
6. Set `GOOGLE_MAPS_API_KEY` only after enabling Routes API. Restrict the key to Routes API and configure quota/budget alerts.
7. Start with Gmail-only authorization at `/auth/google`. It requests exactly `https://www.googleapis.com/auth/gmail.readonly`; when `GOOGLE_ALLOWED_EMAIL` is configured it also requests the identity scopes `openid` and `email` for account allow-list verification. Calendar authorization is disabled by default. To intentionally enable Calendar, set `GOOGLE_CALENDAR_ENABLED=true`, restart the app, and visit `/auth/google/calendar`; that flow requests exactly `https://www.googleapis.com/auth/calendar.events.owned` plus optional `openid` and `email` for the same allow-list check. Both flows use incremental consent (`include_granted_scopes=true`), allowing the Calendar grant to extend an existing Gmail grant. Calendar tools return an authorization-required error until Calendar is enabled and that scope is granted. `/auth/status` does not expose OAuth scopes or tokens. Revoke the old combined grant in Google before reconnecting if you previously authorized both scopes and want Gmail-only access.

OAuth state is 256-bit random, expires after ten minutes, and is consumed once. State hashes and encrypted access/refresh credentials are persisted when PostgreSQL is configured. Refreshed token expiry and refresh credentials are retained. Without PostgreSQL, OAuth credentials remain in process memory and reconnect is needed after restart.

Gmail searches at most ten matching message IDs and retrieves message payloads (not attachments) for conservative, bounded parsing. Returned candidates contain neither full message bodies nor booking-reference values. All email-derived values are untrusted and cannot authorize Calendar actions. Calendar previews remain read-only; this phase does not call Calendar writes.

For public web search, obtain a Brave Search API subscription key and set `BRAVE_SEARCH_API_KEY` in `.env`. `search_travel_web` returns Brave's result title, returned URL, snippet, host, retrieval time, and provider-supplied page age where available. `officialDomain` adds a Brave `site:` query and reports host matching; TripSync does not independently validate ownership of that domain. Empty successful searches are `live` with no results, provider/configuration errors are `unavailable`, and Google demo fixtures are `simulated`. Brave web search has no synthetic fallback.

To verify Gmail retrieval locally, configure the OAuth client and authorize the intended test account at `/auth/google`, then build and start with `npm run build` and `npm run start`. Use the MCP Inspector with `http://localhost:3000/mcp` (and the bearer token header if configured) to call `search_booking_emails`. This Gmail flow does not request Calendar scope. Enable Calendar separately only when you intend to use Calendar tools. Ordinary automated tests use mocked providers and do not need personal email or live API keys.

For current transactional prices, inventory, bookings, or authoritative travel schedules, use the travel provider's official API where it offers one; indexed web snippets can be stale and do not establish availability or a confirmed price.
